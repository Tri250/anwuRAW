01

背景与目标

Background & Goals

新疆合沐纯牛奶以「200ml 袋装 / 盒装、整箱 16 袋（盒）」的规格进入江西省赣州市市场，采用主仓库 → 地区（赣州市）→ 多门店的分销结构，由业务经理统筹、业务员批发铺市、促销员驻店零售，并执行「买二送半箱」的渠道促销。

现状问题（观察）

  • 订货、发货、回款依赖电话与微信接龙，订单无审批留痕，错漏单与扯皮时有发生；
  • 总仓与各门店库存分散记录，看不见实时水位，断货与积压并存，赠品成本无法核算；
  • 「买二送半箱」由各终端口头执行，促销口径不一，业务经理无法核对赠品投放；
  • 总经理缺少统一看板，业绩、回款、库存全靠月底手工汇总 Excel。

产品响应与可观察结果

  • 批发订单线上创建 → 审批 → 出库 → 回款闭环，每张单据可追溯；
  • 总仓 / 门店库存按最小单位（袋、盒）实时记账，任何时点可查水位与流水；
  • 促销规则由系统在开单时自动计算与发放，赠品行独立记录、可汇总审计；
  • 四类角色登录即见各自工作台，业绩与回款按日自动汇总。

共享业务规则（唯一口径）

Shared Rules

R1 · 单位换算

库存与出库一律以最小单位（袋 / 盒）记账；1 箱 = 16 最小单位。界面统一以「X 箱 Y 散」呈现（Y < 16）。允许散件销售与散件调拨。

R2 · 价格

批发价 ¥50/箱，零售价 ¥58/箱；散件单价 = 箱价 ÷ 16 四舍五入到分（批发 3.13、零售 3.63）。价格调整仅总经理可操作，调整后仅对新订单生效，历史单据不追溯。

R3 · 促销「买二送半箱」

同一 SKU 在单笔订单内，净购买整箱数（不含散件、不含赠品）每满 2 箱，自动赠送同 SKU 0.5 箱 = 8 最小单位：

  • 买 2 箱 → 送 8 袋（0.5 箱）；买 4 箱 → 送 16 袋（1 箱）；买 10 箱 → 送 40 袋（2.5 箱）；
  • 净购不足 2 箱不赠送；散件（<16 的数量）不参与满赠计算；
  • 赠品单价 0 元、金额 0 元，独立「赠品行」展示，随订单一并出库；
  • 赠品数量计入库存扣减与门店收货；
  • 让利价值（报表口径）= 赠品数量 × 对应渠道散件价（批发单按 3.13、零售单按 3.63），不计入应收。

R4 · 金额计算

全程以「分」为整数单位计算，展示两位小数（四舍五入）。应收金额 = Σ 正品行（数量 × 单价）；订单级人工优惠（经理审批时可减免）单独记录；实收金额 = 应收 − 订单优惠；赠品不参与应收。

R5 · 库存记账

  • 采购入库：总仓增加；调拨出库：总仓立即减少；门店确认入库：门店增加；
  • 订单审批不占用库存，出库时实时校验并扣减；库存不足时整行阻塞出库并提示缺口数量；
  • 任何变动生成出入库流水（类型：采购入库 / 调拨出库 / 调拨入库 / 销售出库 / 赠品出库 / 调拨损耗），流水只增不改。

R6 · 单号规则

订单号 PF-YYYYMMDD-XXX（批发）、LS-YYYYMMDD-XXX（零售）、调拨 DB-YYYYMMDD-XXX、采购入库 CG-YYYYMMDD-XXX，序号按日自增。

R7 · 审批与减免

批发订单审批人为业务经理与总经理；审批通过时允许填写订单优惠金额（≤ 应收的 10%），超出需总经理审批 [Assumption, TBD]。驳回必须填写原因，原单返回业务员且数据保留。

功能需求

Functional Requirements · FR-01 ~ FR-18
FR-01

统一登录与身份鉴权

P0
触发
打开系统未登录或会话过期时，进入登录页。
规则
工号 + 密码登录；JWT 令牌有效期 12 小时，过期自动登出；密码以加盐散列存储；连续输错 5 次锁定 10 分钟。
结果
登录成功后按角色进入对应工作台；界面菜单与数据范围按 04 章权限矩阵裁剪，越权访问接口返回 403。
异常
账号停用提示「账号已停用，请联系总经理」；登录后端与移动端行为一致。
FR-02

角色工作台（四套看板）

P0
目的
登录第一屏即回答「今天什么情况、我该做什么」。

FR-07

库存查询与出入库流水

P0
触发
各角色在「库存」页查看其权限范围内地点的实时库存。
展示
每个地点 × 商品显示「X 箱 Y 散（合计 N 最小单位）」；在途数量（调拨未入库）单列。

FR-08

调拨与门店领货

P0
触发 1
业务经理/总经理发起「总仓 → 门店」调拨：选门店、录数量 → 提交即校验总仓库存并扣减，进入「在途」。
触发 2
促销员在本店发起「领货申请」→ 业务经理/总经理审批 → 通过后同上进入「在途」；驳回需填原因。
收货
促销员（或经理代确认）在门店端点「确认入库」，按实收数入库；实收 < 发货时差额记「调拨损耗」流水，单据标记「短少」。
异常
总仓库存不足时禁止提交并提示缺口；在途单不可撤销，只能走收货流程。
FR-09

批发订单（业务员开单）

P0
触发
业务员为名下门店（批发客户）创建批发订单。
录入
选择门店 → 逐行选商品、录入箱数与散件数 → 系统实时显示单价、行金额，并按 R3 自动追加赠品行 → 可填写备注与期望送货时间。
提交
保存草稿或直接提交，进入「待审批」；业务经理与总经理收到待办。
校验
门店必须处于营业状态且归属本人；行数量不得同时为 0；不允许对停用商品开单。
FR-10

订单审批与驳回

P0
触发
业务经理/总经理在「待办」或订单列表处理「待审批」订单。
操作
通过（可填写订单优惠金额，≤ 应收 10%，见 R7）；驳回（必填原因）。
结果
通过 → 「已审批」进入出库队列；驳回 → 终态，原单保留可查，业务员可在待办中看到原因。
FR-11

订单出库与交付

P0
触发
业务经理/总经理对「已审批」订单执行出库。
规则
支持整单出库或分批出库（录入本次实发数量，含赠品）；出库时实时校验总仓库存，不足则阻塞并提示缺口；出库即从总仓扣减并生成「销售出库/赠品出库」流水。
完成
全部出完 → 「已出库」；若应收已结清（现结）→ 直接「已完成」。
FR-12

促销引擎（买二送半箱）

P0

P0

技术架构与端侧交付

Architecture · PC + Android

技术选型（正式版 V1.0 已实现）

  • 后端：Node.js 24 + Express + 内建 SQLite（node:sqlite），零原生编译依赖，单机部署开箱即用；
  • 鉴权：JWT（HS256）+ 角色中间件；密码 scrypt 加盐散列；
  • 前端：原生 ES Module SPA + 自研设计系统（CSS 变量、Noto Sans SC 字体栈、tabular-nums 数字排版）；PC 侧边导航 / 移动底部标签双布局；
  • 图表：轻量 SVG 自绘（趋势、排行、结构占比），无外部 CDN 依赖，内网可运行；
  • 部署：单进程 HTTP 服务（默认 :8080），PC 浏览器直接访问；数据文件 data/hemu.db。

安卓移动端交付路线

  • 路线 A · PWA（V1.0 已内置，推荐）：站点提供 manifest + Service Worker + 应用图标，Android Chrome 打开后「添加到主屏幕」即获全屏、带图标的原生 App 体验，自动更新；
  • 路线 B · APK 打包（V1.1）：同源代码经 Capacitor 封装为 APK 发布（内部分发或应用市场），技术路径已在工程中预留 capacitor.config 说明文档；
  • 离线策略：V1.0 要求在线使用；V1.1 引入开单离线缓存与自动重传。
同源双端：PC 与 Android 共用同一服务端与业务逻辑，角色差异只体现在交互布局——促销员/业务员移动端以「开单」为第一入口，总经理/业务经理 PC 端以「看板与审批」为第一入口。
