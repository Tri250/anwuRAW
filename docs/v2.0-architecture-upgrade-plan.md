# RapidRAW / anwuRAW — 2.0 功能架构升级规划（Architecture Blueprint）

- **文档角色**: 架构蓝图 — 定义 2.0 功能架构的目标形态（TO-BE）与演进路径。承接《2.0 版本升级规划》（产品主题维度）与《2.0 功能模块升级规划》（模块投入维度 M1-M12），本篇回答"代码怎么长"的问题
- **证据基础**: 全仓功能模块清单盘点（后端 44 个 Rust 模块 + 前端 9 大分区约 120 个 TS/TSX + 测试体系 5 入口 + 383 张测试资产 + 5 条 CI 流水线），关键数字均为 2026-10-13 实测
- **硬约束**: 不做商业、不做云服务、端侧为主 —— 架构决策全部向"离线可用、本地优先、单机自洽"收敛
- **日期**: 2026-10-13
- **状态**: Draft — 待评审

## 1. 定位：为什么需要第三个维度

三份规划的分工：

| 文档 | 回答的问题 | 视角 |
|---|---|---|
| 2.0 版本升级规划 | 做什么主题、达到什么指标 | 产品 |
| 2.0 功能模块升级规划（M1-M12） | 每个模块投入多少、先做哪个功能 | 投入 |
| **本篇** | **代码以什么结构承载这些功能、架构债怎么还** | 结构 |

单人维护者是最大约束 → 架构第一原则：**每一步重构必须增量可发版、契约测试先行、不出现"大爆炸重写"**。总规划已明确 Non-Goal：不重写 WGSL 管线 —— 本篇所有引擎侧动作都是"编排重构 + 边界治理"，不是重写。

## 3. TO-BE：2.0 目标功能架构

### 3.1 六层目标架构

```
L5 前端表现层    视图/面板/模态（组件化不变）+ store 分域 + 薄 hooks
L4 接口层        command 分域注册（8 域 façade）· 事件总线 · CLI · .rrdata v2 SDK
L3 应用服务层    用例编排: RenderSession / ImportSession / ExportJob /
                 ComposeJob / IndexService / ModelRuntime
L2 领域服务层    Engine(算子唯一实现) · Masks · AI · Compose · Color ·
                 Metadata · DAM · Export
L1 基础设施层    GPUContext(wgpu) · ORTRuntime(EP 分级) · JobQueue ·
                 Storage trait(POSIX/SAF) · SQLite 索引 · LutStore
L0 资产层        模型库(manifest) · LUT · lensfun_db · ICC profiles ·
                 golden_assets/snapshot_baseline(测试资产)
```

层间规则：**只能向下依赖**；L2 内模块间不得直接 import（走 L3 编排或 trait）；前端只允许触达 L4 分域 façade。

### 3.2 十大架构决策（ADR）

**AR-1 接口分域 façade**（治 AD-3）
128 个 command 按 8 域重组注册：`library` / `editor` / `masks` / `ai` / `compose` / `export` / `metadata` / `system`。lib.rs 从 2,539 行降为纯装配根（<400 行），每域一个 `register_commands(builder)`。command 签名即 DTO 边界（serde 类型入 `api/` 模块），禁止 Value 穿透。
验收：lib.rs 只含装配；每域可独立 `cargo doc` 出接口文档；前端 invoke 调用点与域注册一一对应。

**AR-2 算子单实现 + 目标后端委托**（治 AD-1/AD-11，2.0 引擎侧最关键决策）
- 全部调整算子**只在 WGSL 实现**；CPU 路径只保留三类非算子职责：解码（rawler）、几何（rotate/crop/warp）、编码。
- 缩略图/批量/后台任务不再手写 CPU 算子 —— 无 GPU 时走 **lavapipe 软件后端**（Task 0 已实证：CI 全管线 28s 可跑、结果与硬件路径同源），彻底消灭 `apply_cpu_agx_tonemap` / `apply_cpu_default_raw_processing` 双轨与 raw_default 豁免项。
- 中间缓冲统一 16bit float（治 AD-11 量化链）。
- 兜底：lavapipe 不可用的极端环境（无 Vulkan loader）降级为"CPU 最小路径 = 仅解码+编码，调整算子禁用"并明确告知，不再维护双实现。
- 迁移安全网：contract tests 367 例快照 + 48 对一致性作为重构护栏，每步全绿才可合入。
验收：`apply_cpu_*` 算子函数清零；raw_default 豁免从 WHITELIST 移除且一致性全绿；低端设备用例回归通过。

**AR-3 色彩管理中枢**（治 AD-7，对齐 M1-E2/M10）
新建 `color/` 领域模块：工作空间（scene-linear）为管线唯一内部色彩空间，显示与导出均为"工作空间→目标 ICC"的单向变换；ICC profile 资产入 L0（sRGB/AdobeRGB/P3），soft proofing 为中枢的直接消费方。终结"wgpu 升级导致 P3 色偏"类补丁。
验收：P3/sRGB/AdobeRGB 显示用例零色偏；导出嵌入 ICC 被色彩感知软件正确识别。

**AR-4 数据层：索引 + 版本化**（治 AD-2/AD-5，对齐 M2-D1）
- **SQLite 索引库**（rusqlite，库文件置于应用数据目录）：EXIF/评分/标签/编辑状态/缩略图指纹的持久化索引，增量刷新；文件系统仍为图像二进制的事实源，索引可随时重建（可牺牲性设计）。
- **`.rrdata` v2**：顶层 `schema_version` + 迁移链框架（v1→v2 一次性，写前 .bak），未知字段保留；JSON Schema 公开。
验收：10 万张库冷启动索引 < 3s、搜索 < 100ms；种子 .rrdata 回放零丢失。

**AR-5 文件域拆分**（治 AD-4，配合 AR-4 串行执行）
file_management 按职责拆四：`library_scan`（扫描/监听）、`thumb_service`（缩略图管线）、`file_ops`（复制/移动/重命名）、`metadata_repo`（读写入口，转接 SQLite）。42 个 command 随域并入 AR-1 分组。
验收：四模块各 < 1,500 行；行为由快照式图库操作回归用例锁定。

**AR-6 蒙版数据模型 v2**（治 AD-6）
蒙版参数从 uniform 定长数组迁到 **storage buffer + 蒙版图集纹理**，容量上限从 32 提升为内存约束（目标 ≥ 256）；MaskDefinition 结构版本化随 `.rrdata` v2。
验收：40 蒙版容器场景无渲染错误；旧文档 32 蒙版迁移无损；契约测试蒙版用例扩容全绿。

**AR-7 AI 运行时统一**（治 AD-8，承接 v2-ondevice-ai spec 的 model_manifest 既有工作）
四层收敛：`ModelManifest`（已在途）→ `ModelManager`（下载/校验/版本/存储路径唯一入口）→ `InferenceRouter`（ort 会话池 + EP 分级：CoreML/NNAPI/CPU，按模型×设备选档）→ `CapabilityAdapter`（mask/inpaint/denoise/blur 各能力只写适配层）。`ai_connector`（ComfyUI 自托管）作为可选 Adapter 保留，不进入核心依赖图。
验收：新增一个 AI 能力只需 manifest 条目 + 适配层；模型断点续传 + sha256；全功能离线。

**AR-8 统一任务队列**（治 AD-9，对齐 M3-X4）
`JobQueue` 基础设施：持久化任务表（SQLite 同库）、暂停/续跑/重试/进度事件；export / compose（HDR/全景/堆栈）/ ai 批处理 / library 首次索引全部接入。取消现有分散的 rayon 直跑 + 前端轮询。
验收：100 张导出中断续跑不重复；四个场景共用同一队列与进度协议。

**AR-9 平台抽象层**（治 AD-10）
`platform/` 模块收敛全部 OS 分支：文件访问（POSIX vs Android SAF）、窗口、启动参数、崩溃日志导出。业务模块禁止出现 `#[cfg(target_os)]`（tethering 等编译期 feature 除外）。
验收：`grep -r "cfg(target_os" src/ --include=*.rs` 仅命中 platform/ 与 build 入口。

**AR-10 前端单数据流渲染**（治 AD-12）
渲染链路收敛为状态机进 `useProcessStore`：`idle → dirty → debounced → rendering → ready/error`，防抖/取消/竞态治理在 store 内闭环；21 个 hooks 瘦身为纯绑定层。`adjustments.ts`（前端 70+ 参数定义）与后端 `param_matrix.rs` 建立**参数契约校验测试**（两侧 key/scale 对齐 CI 断言），防止前后端参数漂移。
验收：滑杆 p95 < 50ms（4K RAW）；快速拖动零渲染竞态（自动化连点测试）；参数契约测试入 CI。

### 3.3 目标数据流（四条主链路）

| 链路 | TO-BE 路径 |
|---|---|
| 拖滑杆 | 面板 → store 状态机（防抖/取消）→ editor 域 façade → RenderSession → Engine（单实现 WGSL）→ 16bit 缓冲 → 画布 |
| 导入万张库 | ImportSession → library_scan → JobQueue(索引) → SQLite → 虚拟化网格（缩略图经 thumb_service GPU 管线） |
| 批量导出 | ExportJob 入队 → 队列调度 → Engine + Color 中枢（ICC）→ 编码 → 持久化进度/续跑 |
| AI 蒙版 | AIPanel → ai 域 façade → ModelRuntime（manifest 校验 → Router 选 EP）→ CapabilityAdapter → 蒙版图集 |

## 7. 裁剪与不做

**不做**（架构 Non-Negotiables）：
- 不重写 WGSL 管线为多语言/通用引擎（总规划 Non-Goal 维持）
- 不引入微服务/进程隔离（单机单进程，复杂度不匹配）
- 不做插件系统（2.1+ 评估；接口分域 façade 已为其预留扩展点）
- 不自建云同步/遥测服务端（端侧约束）

**可裁剪顺序**（带宽不足时后移）：FE-2 hooks 瘦身 → MSK-2 解耦 → CMP-2 → PLT-4 → QA-1 会话级（迁移级不可裁）。
**不可裁剪**：AR-2（双轨根治）、AR-4（数据层）、AR-1（接口分域）、QA-1 迁移级测试 —— 四项是 2.0 "可信"叙事的结构承重墙。
