# RapidRAW / anwuRAW — 2.0 子功能模块升级规划（含专家级自检）

- **文档角色**: 第四层规划 — 将《2.0 功能模块升级规划》的 M1-M12 下钻到**每一个子功能模块**（后端 44 个 Rust 模块 + 前端 9 大分区全部组件），并在文末附专家级产品经理视角的完整自检记录（含发现的问题与修正）
- **优先级约定**: P0 = 2.0 必达（不可裁剪）· P1 = 2.0 尽量 · P2 = 2.1+ 候选（裁剪池）；里程碑对齐 M0-M4
- **硬约束**: 不做商业、不做云服务、端侧为主 —— 每个升级项均已做端侧一致性核查（见自检 F5）
- **日期**: 2026-10-13 · **状态**: Draft v1.1（自检修正后）
- **规划体系**: 总规划（主题）→ M1-M12（模块投入）→ **本篇（子模块功能）** → AR-x（架构动作，见 v2.0-architecture-upgrade-plan）

---

## 4. 专家级产品经理自检记录（深度完整自检）

> 以下为以资深 PM 视角对本篇及三份既有规划做的交叉自检。**每项发现均已在上述 v1.1 文本中修正**，此处保留推理过程供评审追溯。

### F1 覆盖完整性检查 ✅（发现 1 处缺口 → 已补）

逐条核对功能模块清单：后端 44 模块（38 根文件 + 6 子目录包）全部出现在第 1 章表格；前端 9 分区全部出现在第 2 章。**发现的缺口**：`multi_exposure` 在 M1-M12 模块规划中无归属（HDR 有、multi_exposure 没有）——已在 1.4 显式定位为 CMP 域成员（P2），避免"清单上有、规划里无"的暗坑。同理显式定位的还有 `cache_utils`、`launch_request`、`ExternalEditBar`、`CommunityPage`。

### F2 与既有决策的一致性 ✅（发现 2 处越权 → 已收敛）

- 自检初稿曾为 `camera_tethering`/`TetheringPanel` 写了"联拍会话恢复"增强项 —— **与 M12 C 级"维护模式"决策冲突**，且 Windows 不做是 README 已论证的技术决策。已收敛为纯维护。
- `window_customizer` 同理：与 2.0 主叙事（可信/端侧/专业工作流）无交集，保持维护模式。
- PM 纪律：**规划的价值一半在"不做什么"** —— 维护模式必须显式声明，否则会被后续迭代当成"可加功能"的空地。

### F3 端侧约束穿透检查 ✅（发现 2 处风险 → 已处理）

逐项扫描全部升级项的网络依赖：
- **地图视图（M2-D3）**：OSM 瓦片默认需要网络 —— 端侧定位下改为"离线瓦片包为可选下载 + 在线瓦片仅显式开关"。此项在模块规划中未言明，本篇已补（风险转记 M2-D3 验收）。
- **CommunityPage**：GitHub 静态内容属于"读公开资源"而非"自建云服务"，不违约束；但必须处理**离线降级**与**导入预设安全校验**（已列入 2.2，P1）。
- AI 全项：ModelManager/EP/量化均为端侧，`ai_connector` 降级为可选 adapter（默认关闭）—— 一致。
- 结论：**零新增网络依赖**，两处既有项已完成端侧化改造设计。

### F4 验收可度量性 ✅（发现 5 处模糊表述 → 已量化）

自检中把所有"优化体验/提升性能"类模糊语改为可测试断言。例："缩略图更快" → "滑杆期间缩略图任务自动让路（自动化断言）"；"蒙版好用" → "40 容器场景可导航可命名（快照断言）"。当前 v1.1 中**不存在无量化验收的 P0/P1 项**（维护模式项豁免，因其验收即"无新增"）。

### F5 单人带宽核算 ⚠️（最大风险 → 已建立裁剪池）

统计 v1.1 承诺：**P0 共 19 项**（引擎 4 + 数据 3 + AI 2 + 导出 1 + 前端 4 + 测试 3 + 平台 2），P1 共 22 项，P2 共 14 项。对照 M0-M4 节奏（单人 + AI 辅助开发）：
- P0 19 项分布在 M0-M3 四个里程碑，M1 峰值 7 项 —— 其中 AR-1/PLT-2（command 分域）与 AR-2（算子单实现）为最高风险并行项，**错峰执行：M1 先做 AR-2（契约测试已就绪、风险最高），AR-1 机械拆分放 M1 末-M2 初**；
- P2 14 项 = 显式裁剪池，与总规划"可裁剪顺序"合并维护，带宽不足时按序后移，无需重新规划；
- 新增裁剪规则：**任何 P1 项不得在其前置 P0 项未验收时启动**（防止半成品栈叠）。

### F6 依赖闭环检查 ✅（发现 1 处环 → 已拆解）

依赖图核验发现一处潜在环：`FE-1 渲染状态机`依赖 `AR-2 算子单实现`的会话语义，而 `AR-2 验收`又需要前端配合回归 —— 拆解为：AR-2 先以 harness 级验收（契约测试全绿）独立闭环，FE-1 再接入生产链路并以同一套契约测试做端到端验收。其余链路（AR-4→FIL-1→FIL-3→D2/D3；AR-7→AIPanel；AR-8→EXP-1/CMP-1）单向无环。

### F7 与架构蓝图（AR-x）双向映射核对 ✅

AR-1~AR-10 每项在本篇至少有一个 P0 承接行（AR-9→android_integration 收敛、AR-10→store 状态机等）；反向核对第 1/2 章每个 P0 行均有 AR-x 或 M-x 归属 —— 双向闭合，无"孤架构决策"或"孤功能项"。
