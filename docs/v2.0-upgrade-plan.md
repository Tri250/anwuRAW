## 1. 战略定位

**1.x 的故事**是"功能追平"：11 个月内堆叠了 AI 蒙版/修复、联机拍摄（Tethering）、HDR 合成、全景拼接、焦点堆栈、胶片模拟、CLI、Android 端 —— 功能面已对齐 Lightroom 替代品的主张。

**2.0 的故事**必须换成"**从功能完备的产品 → 可信赖的专业工作流平台**"。理由：

1. 审计显示瓶颈已不在功能，而在**信任链**（签名/更新/测试/CSP）与**架构可持续性**（.rrdata 无版本化、CPU/GPU 双轨、品牌分裂）；
2. README 官方 priorities 的前两条就是 Astro Stacking 之外的"Bug Fixes & Stability"—— 项目自证已进入稳定性回报期；
3. **产品决策已定调：不做商业、不做云服务，以端侧为主** —— 现有"本地内置 + 自托管 ComfyUI"双轨 AI 架构正是这一方向的雏形，2.0 将其强化为全功能离线可用的端侧体验；`@clerk/react` 云账号依赖转为死重，列入清理清单。端侧优先即是与 Adobe 订阅制最大的差异化。

> **2.0 一句话主张**: "Same speed. Now trusted. Always offline."（同等速度，从此可信，全功能离线可用）

## 2. 目标与北极星指标

| 目标 (GA 后 90 天) | 指标 | 目标值 |
|---|---|---|
| 可信 | 崩溃率（crash-free sessions） | ≥ 99.5% |
| 可信 | 自动更新启用率 | ≥ 70% |
| 可信 | 后端核心模块测试覆盖率 | ≥ 60%（当前无 CI 测试） |
| 流畅 | 滑杆实时预览 p95 延迟 | < 50 ms（4K RAW） |
| 增长 | D30 留存（桌面） | ≥ 35% |
| 端侧 | AI 功能离线可用率 | 100%（无任何功能依赖联网服务） |
| 端侧 | 端侧 AI 性能（中端 Android AI 蒙版） | < 2 s |

**Non-Goals（2.0 明确不做）**: 云服务/账号体系/订阅商业化（产品决策：端侧优先）；重写 WGSL 管线为多语言引擎；引入插件市场；视频编辑；人脸识别（隐私争议 + 成本，延后评估）。

## 3. 四大主题

### T1 信任与分发底座（Trust）— 直接消化审计 P0/P1

范围：
1. **签名矩阵**: Windows Authenticode、macOS Developer ID + 公证、Android 正式 keystore（secrets 硬校验）、Linux 保持包管理器渠道。
2. **自动更新**: `tauri-plugin-updater` + minisign 签名的 latest.json，以 GitHub Releases 为更新源（无自建服务），全平台静默/提示更新，支持回滚通道（stable / beta 双轨）。
3. **CI 门禁硬化**: `cargo test` + `vitest` 入 CI 并阻断；lint/format/i18n 去 `continue-on-error`；CSP 非空断言；版本号三处一致性断言。
4. **供应链**: tauri-action 回退官方 release tag；ORT 改为固定资产 + sha256；rawler fork 打 tag 固定 rev；产出 SPDX SBOM。
5. **可观测性**: 崩溃上报遵循端侧优先 —— 默认本地日志导出，可选自托管上报端点（如 GlitchTip），开关默认关闭；错误边界全覆盖。

验收门槛（= 审计 Go/No-Go 全绿 + crash 看板上线）。

### T2 引擎与数据 2.0（Engine & Data）

范围：
1. **`.rrdata` v2 格式**: 顶层 `schema_version` + 迁移链（v1→v2 一次性迁移，写前自动备份 `*.rrdata.bak`）；未知字段保留（向前兼容）；提供 JSON Schema 公开文档，服务第三方 CLI/脚本生态。
2. **CPU/GPU 处理统一契约**: 当前 CPU 后备路径（dehaze/glow/channel mixer 等逐个手写）与 WGSL 管线行为存在漂移风险；建立"调整项契约测试"—— 同一输入在 CPU/GPU 路径输出差异 ΔE < 1。
3. **色彩管理端到端**: v1.6.10 起 wgpu 降级修 P3 色偏是补丁式修复；2.0 将 ICC profile（sRGB/AdobeRGB/Display P3）贯穿 解码→编辑→导出 全链路，消除"显示器相关性"问题类。
4. **性能基准体系**: 以现有 `bench/` 为基础建立发版回归基线（打开 50MP RAW、拖滑杆、导出、库浏览 1 万张四个场景），每版 CI 出性能报告，防"修好一处慢三处"。

验收：迁移向导零数据丢失（种子库 10,000 个真实 .rrdata 样本回放）；性能基线全绿；色彩管理通过 #2831 P3 显示器用例回归。

### T3 平台矩阵与端侧 AI（Platform & On-Device AI）

范围：
1. **Android 正式化**: 签名合规、Play 商店上架（targetSdk 36 已达标）、大屏/折叠屏适配、移动端性能档位（静态预览模式默认化）。
2. **iOS 评估/Alpha**: Tauri 2 已支持 iOS；2.0 周期内出 TestFlight alpha（只读浏览 + 基础调整，不做全功能承诺）。
3. **Linux 稳定性专项**: webkit2gtk pin 解锁评估、Wayland/NVIDIA 边缘问题收口（README FAQ 中的两大 crash 类别）、GPU 后端自动选择策略升级。
4. **端侧 AI 强化**（产品决策：不做云服务，AI 全部本地）: 模型量化分级（INT8/4bit）与蒸馏、NPU/GPU 委托加速（Android NNAPI / macOS CoreML / Metal）、生成式填充端侧大模型作为可选下载包；移除 `@clerk/react` 云账号死重依赖；保留 ComfyUI 自托管作为高级用户的"自建算力"通道。

验收：Android 通过 Play 审核；AI 全功能离线可用；中端 Android 机型 AI 蒙版 < 2s；安装包与模型体积分级达标。

## 4. 里程碑

```
M0 止血（2-3 周）      → 1.6.15 hotfix train：审计 P0-1~P0-6 全部落地
M1 Alpha（+6 周）      → T1 全绿 + .rrdata v2 冻结 + 迁移框架 + 内部 dogfood
M2 Beta（+8 周）       → 端侧 AI 强化落地、Android 正式化、天文堆栈 Beta、覆盖率 ≥60%
M3 RC（+4 周）         → 全平台 RC、迁移演练（1.6→2.0 真实库回放）、13 语言 i18n 冻结
M4 GA                  → 复用审计 Go/No-Go 检查单放行；stable/beta 双通道开启
```

范围裁剪机制：单人维护者带宽是最大约束 —— M2 结束时若天文堆栈未达 Beta 质量，降级为 2.1 旗舰，**信任底座（T1）与数据迁移（T2-1）不可裁剪**。

## 5. 数据迁移策略（1.x → 2.0）

吸取 v1.4.0 标识符变更事故教训（metainfo 中"presets will be gone"）：

1. **双读单写**: 2.0 可读 v1 `.rrdata`/预设/设置，首次保存时写 v2 + 保留 .bak；
2. **迁移向导**: 首启检测旧数据 → 展示迁移清单 → 一键迁移 → 结果报告（成功/跳过/失败计数）；
3. **应用标识符不变**: 继续使用 `io.github.CyberTimon.RapidRAW` 数据目录，杜绝二次迁移事故；
4. **回滚开关**: 设置页提供"以 v1 兼容模式打开"逃生通道（一个版本周期内有效）。

## 7. 待决策问题（Open Questions）

1. **品牌收敛终局**: 全面更名 anwuRAW，还是回归 RapidRAW？影响 flatpak id / 域名 / 社区资产，需在 M1 冻结。
2. **崩溃上报方案**: 端侧优先原则下，建议默认"本地日志导出 + 可选自托管上报端点（如 GlitchTip）"，不引入商业 SaaS —— 是否内置需定稿。
3. **设备间流转方案**: 无云同步后，预设/设置跨设备迁移以"打包导出导入 + `.rrdata`/配置文件天然可被用户自有网盘同步"为官方零服务端路径 —— 是否需要专门的一次性迁移向导？
4. **iOS 投入度**: TestFlight alpha（本计划假设） vs 完整上架（+6 周）？
5. **2.0 是否顺带最小系统要求升级**: macOS 13→14、Win10→Win11 可选支持？影响 QA 矩阵规模。
