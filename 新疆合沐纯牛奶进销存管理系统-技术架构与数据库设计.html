新疆合沐纯牛奶进销存管理系统

技术架构与数据库设计 · 与 PRD V1.0 对齐 · 供后端 / 前端 / 移动端开发
版本：V1.0 目标端：PC Web + Android 业务域：快消品分销进销存

1架构概述

系统采用 前后端分离 + 移动端 的单体优先（Modular Monolith）架构：一个后端应用按业务域拆分为清晰模块，前端分 PC 管理端与 Android 移动端，两端共用同一后端 API。该选型兼顾小团队快速交付与后续拆分演进。

4核心业务流程与事务边界

4.1 门店要货 → 出库 → 签收 → 应收

4.2 采购入库 / 销售退货 / 回款核销（要点）

  • 采购入库：验收入库（增加批次库存 + 记录流水）与生成应付在同一事务；录入生产日期自动推导到期日。
  • 销售退货：收货判定「可再售 / 报损」，可再售回库（加批次 + 流水），同时冲减应收；两处需同事务。
  • 回款核销：登记回款 + 按 FIFO 核销应收，需用行锁避免并发重复核销；使用 Redis 幂等锁防重复提交。
  • FIFO 出库：按到期日升序锁定批次并扣减，需在数据库行锁定批次行防超卖。
一致性原则：任何「库存增减 + 单据/资金变化」的成对动作必须置于同一数据库事务；并发扣减用行锁；重复提交用幂等键（如订单号 + 操作类型）。

5.4 关键索引建议

  • inventory_lot：(warehouse_id, product_id, expire_date) 支持库存查询与 FIFO；(status, expire_date) 支持临期/过期扫描。
  • sales_order：(store_id, status)、(order_no) 唯一。
  • receivable：(store_id, status, due_date) 支持逾期扫描。
  • inventory_flow：(ref_no)、(warehouse_id, product_id, created_at)。
交付说明：本文与 PRD 业务规则一一对齐（SKU、批次、FIFO、效期、账期额度、审批、促销投入产出），可作为后端建库与接口开发、前端与移动端联调的直接依据。金额精度统一 2 位小数，数量统一最小单位整数。
