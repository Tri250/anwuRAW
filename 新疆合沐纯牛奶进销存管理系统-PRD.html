2. 背景与目标

观察到的业务问题：乳品为短保质期快消品，进销存依赖批次与效期；赣州区域经销商存在多仓库 / 门店铺货、客户普遍赊销月结的特点。若依赖手工台账或零散表格，会出现以下问题：

  • 库存批次与效期不可追踪，临期 / 过期商品无法及时识别，存在食品安全与报废损失风险；
  • 赊销账目以手工记录，客户应收、供应商应付、对账核销易出错、易漏记；
  • 多仓库 / 门店库存数据不互通，难以调拨与盘清；
  • 业务员现场开单、查库存、确认欠款缺乏工具，效率低且易超信用额度发货。

受影响用户与关键时刻：采购员在制定进货计划时、仓管员在出入库与效期管理中、业务员在客户现场开单与收款时、财务在做客户 / 供应商对账时、老板在做经营决策时。

产品决策：建设一套以「批次效期 + 应收应付」为核心的进销存系统，PC 端支撑后台全流程管理与经营分析，Android 端支撑业务员现场开单、收款、查库存与查欠款。

可观测的产品结果（定性）：

  • 每一笔入库、出库都能追溯到具体批次与到期日；临近效期商品可提前预警并优先出清；
  • 每一笔赊销都能自动形成应收，收款可逐单核销，任一客户余额实时可查且可对账；
  • 多仓库 / 门店库存实时互通，支持跨点调拨与盘点；
  • 业务员现场即可完成开单收款，超信用额度时被明确拦截或提示。

本节为文档核心。每个模块按「用途 → 触发 → 处理规则 → 结果 / 状态变更 → 字段 → 状态 → 权限 → 异常」组织；跨模块共享规则统一在第 6 节定义，此处仅引用。

5.1 基础资料

5.1.1 商品与分类管理（FR-MD-01）

用途：建立袋装 / 盒装牛奶的商品档案，作为进、销、存、账的唯一商品锚点。

触发：管理员 / 采购员在 PC 端新增或编辑商品。

字段：

字段必填规则
商品编码是系统内唯一，可自动生成不可重复
商品名称是重复时警告但不拦截
一级分类是袋装 / 盒装（可扩展）
规格是容量 / 净含量，如 250mL
基本单位 / 整箱单位是如「袋 / 箱」并维护换算率（1 箱 = N 袋）
保质期天数是正整数，用于自动计算到期日
进价参考 / 零售价 / 批发价是价格取数来源，销售时按客户价格级别带回可改
最低库存（安全库存）否低于此值触发低库存预警
批次管理标识是牛奶默认开启，不可关闭
状态是启用 / 停用

处理规则：已发生业务（有单据引用）的商品不可删除，只能「停用」；停用商品不可新建单据，历史数据保留可查。

异常：商品编码重复 → 拦截提交；保质期天数 ≤ 0 或非整数 → 拦截；换算率 ≤ 0 → 拦截。

5.1.2 仓库 / 门店管理（FR-MD-02）

字段规则
地点编码 / 名称唯一，必填
类型仓库 / 门店（仓库为存货点，门店为销售点位，均可作出库仓）
地址 / 负责人选填，用于配送与责任归属
状态启用 / 停用；停用后不可参与新单据

规则：地点是库存数据与员工数据权限的边界（见 6.5 权限矩阵）。同一商品在不同地点分别保有独立批次库存。

5.1.3 供应商管理（FR-MD-03）

字段规则
供应商编码 / 名称唯一，必填
联系人 / 电话 / 地址选填
结算方式赊销（月结）为主，可配账期天数
应付余额只读，由采购与付款单据自动汇总（见 6.3）
状态启用 / 停用

5.1.4 客户管理（FR-MD-04）

字段规则
客户编码 / 名称唯一，必填
联系人 / 电话 / 地址必填（配送与联系需要）
价格级别如零售价 / 批发价 / 专属价，决定销售默认取价
结算方式赊销 / 现款；赊销销售生成应收，现款销售直接形成收款
信用额度赊销客户可选填，未填视为不限额
应收余额只读，由销售与收款单据自动汇总（见 6.3）
状态启用 / 停用；停用客户不可新建销售单

异常：客户编码重复拦截；现款客户不参与信用额度校验。

5.1.5 员工与账号管理（FR-MD-05）

字段规则
账号 / 姓名 / 手机号必填，账号唯一；手机号用于登录与通知
角色见 4.1 角色，1 人可多角色（权限取并集）
可访问地点见 6.5 数据权限，决定可见仓库 / 门店范围
状态启用 / 停用；停用后即时无法登录

5.2 采购管理

5.2.1 采购入库（FR-PUR-01）

用途：记录向供应商采购牛奶入库，形成批次库存并增加应付。

触发：采购员新建采购入库单（可直接入库，也可由采购订单生成，采购订单为 P1）。

处理流程：

选择供应商→ 录入明细（商品/批次/生产日期/数量/进价）→ 自动算到期日与金额→ 提交审核→ 审核通过 · 入库生效

处理规则：

  • 批次号可自动生成（建议：采购单号 + 序号）或手动录入厂家生产批次号；
  • 到期日 = 生产日期 + 商品保质期天数，自动计算，可纠正但须提示；
  • 单据金额 = ∑（数量 × 进价），折扣与税额处理见 6.3；
  • 审核通过后：对应地点增加该批次库存数量，同时增加该供应商应付账款余额。

结果 / 状态变更：单据由「待审核」→「已审核」，库存与应付同步生效（状态机见 6.1）。

5.2.2 采购退货（FR-PUR-02）

用途：向供应商退回问题商品，减少批次库存并冲减应付。

规则：选择供应商、商品、具体批次、退货数量；退货数量 ≤ 该批次当前库存；审核通过后减少对应批次库存、冲减应付。

异常：退货数量超过库存 → 拦截；所退批次已过期 → 允许（退回供应商），但需备注原因。

5.2.3 采购订单（FR-PUR-03 · P1）

预采购计划单据，不产生库存与应付。到货后可一键「生成采购入库单」，支持部分到货。非核心路径，不影响 5.2.1 直接入库。

5.3 销售管理

5.3.1 销售出库（FR-SAL-01）

用途：向客户销售牛奶，按 FEFO 扣减批次库存，形成应收或收款。

触发：业务员（PC 或 Android）新建销售出库单。

处理流程：

选择客户→ 选商品/数量（取价级别默认价）→ 信用额度校验→ 保存 · FEFO 分配批次→ 提交审核→ 出库生效

处理规则：

  • 售价按客户价格级别默认带回，可手工修改；折扣处理见 6.3；
  • 赊销客户：审核后增加应收；现款客户：审核后直接生成收款（记现金 / 转账）；
  • 信用额度：赊销客户在「应收余额 + 本单应收金额 ≤ 信用额度」时放行，超限行为见 6.4；
  • 批次分配遵循 FEFO 规则（见 6.2），支持有权限的手动指定批次；
  • 库存不足：默认拦截提交，提示缺货数量与可售库存。

结果 / 状态变更：审核通过后，按分配批次扣减库存，客户应收余额增加（或以现款形成实收）。

异常：库存不足、信用超限、客户停用、商品停用、批次已过期（默认禁止销售出库，仅可报废）。

5.3.2 销售退货（FR-SAL-02）

用途：客户退货回库，增加批次库存并冲减客户应收。

规则：选择客户、商品、数量，并指定回库存放批次（可新建退货批次沿用原到期日，或按原批次）；审核后增加库存、冲减应收。

异常：退回商品已过期 → 入「待报废」冻结仓，不进入可售库存。

5.3.3 移动端现场开单（FR-SAL-03）

用途：业务员在客户现场快速开单、收款、退货、查欠款，与 PC 端共用同一单据流。

能力说明
快速开单选客户 → 选商品 → 数量 → 提交；支持扫商品条码 / 输入编码
现场收款开单后引导收款登记（现金 / 扫码转账），核销本次应收
欠款与对账查看客户应收余额、账期、未结清单
库存与效期查看各仓批次库存与临期情况，避免缺货 / 推临期
凭证拍照单据 / 收货签字 / 收款凭证拍照留存 TBD

网络：在线实时为主；离线开单为可选能力 TBD，未确认前按在线设计。

5.4 库存管理

5.4.1 库存查询（FR-INV-01）

用途：按地点 / 分类（袋装、盒装）/ 商品 / 批次，实时查看数量与效期。

查询维度展示内容
汇总库存商品在各地点 / 全公司总数量（分袋装、盒装）
批次库存批次号、生产日期、到期日、剩余天数、数量、状态（在库 / 临期 / 过期）

5.4.2 批次与效期管理（FR-INV-02）

用途：以批次为库存最小单元，落地 FEFO，简化规则见 6.2。

  • 临期预警：到期前 N 天（可配置，默认 30 天 假设 TBD）进入临期，推送预警并支持一键「优先出清」；
  • 过期批次：自动标记为「已过期」冻结，默认禁止销售出库，只能走报废流程；
  • 报废：生成报废单，减少批次库存并记损益，需审核留痕（见 6.6）。

5.4.3 库存调拨（FR-INV-03）

用途：同一主体内不同地点之间调拨商品（含批次迁移）。

状态流转：草稿 → 待出库 → 在途 → 已完成；可作废。

规则：源地点按 FEFO 扣减、目标地点录入实收批次与数量；调拨在途数量单独可见。

5.4.4 库存盘点（FR-INV-04）

用途：核对账实，处理盘盈盘亏。

流程：新建盘点单（选地点、商品或分类）→ 录入实盘数量（含批次）→ 提交 → 审核通过 → 生成盘盈 / 盘亏并调整库存。

规则：盘点差值需填写差异原因；盘亏需审核留痕（见 6.6）。

5.4.5 库存预警（FR-INV-05）

统一预警规则见 6.4，覆盖两类：

  • 效期预警（临期 / 过期）；
  • 低库存预警（低于商品安全库存）。

5.5 财务与对账

5.5.1 应收 / 应付台账（FR-FIN-01）

用途：按客户 / 供应商汇总往来余额与明细，支持按单据下钻。

台账维度内容
应收台账客户期初 + 销售 − 退货 − 收款 = 实时余额
应付台账供应商期初 + 采购 − 采购退货 − 付款 = 实时余额

余额计算规则见 6.3。

5.5.2 收款 / 付款核销（FR-FIN-02）

收款单：选择客户 → 录入收款金额与方式（现金 / 银行 / 扫码）→ 核销其应收（支持按单据逐笔核销或部分核销）。

付款单：选择供应商 → 录入付款金额与方式 → 核销其应付。

规则：核销后相应余额实时冲减；支持「预收 / 预付」计入余额但不绑定具体单据。

异常：收款金额大于客户应收余额 → 允许（差额记预收）但需提示；核销的单据必须已审核。

5.5.3 客户对账单（FR-FIN-03）

用途：按客户生成一段期间的往来对账单，供月结核对与打印 / 发送。

内容：期初余额、期间销售汇总与明细、退货、收款、期末余额；分袋装 / 盒装汇总数量与金额。

6. 共享规则

6.1 单据状态机

进销存业务单据（采购入库 / 采购退货 / 销售出库 / 销售退货 / 盘点）：

草稿→ 待审核→ 已审核（生效）
状态可执行操作
草稿编辑、删除、提交、作废
待审核审核通过、驳回（回到草稿）、作废
已审核只读；如需撤销走「红冲」反向单据（如退货 / 负库存调整），不可直接改删 假设 TBD

调拨单：草稿 → 待出库 → 在途 → 已完成（可作废）。

已审核单据不可直接编辑删除。更正方式统一为「反向单据 + 留痕」，保证账务与审计可追溯。

6.2 FEFO 出库规则

定义：销售出库（及调拨出库）时，按批次到期日最早优先自动分配可售库存。

分配顺序：同一商品在同一地点，先按「到期日由早到晚」，到期日相同再按「批次号升序 / 入库时间最早」。假设 TBD

约束：

  • 「已过期」批次不参与自动分配，默认禁止销售出库；
  • 支持有权限用户手动指定批次出库，但所选批次须库存充足且未过期（过期须走报废）；
  • 分配的批次与数量在审核通过时锁定扣减，避免并发超卖。

6.3 计算规则

项目规则
单据金额∑（数量 × 单价）− 折扣；支持整单折扣与单品折扣，折扣后金额四舍五入到分
税额价税处理默认按「含税一口价」 假设 TBD；如需价税分离，税率统一配置
应收余额Σ 已审核销售金额 − Σ 已审核销售退货金额 − Σ 已核销收款
应付余额Σ 已审核采购金额 − Σ 已审核采购退货金额 − Σ 已核销付款
批次库存Σ 已审核入库 − Σ 已审核销售出库 − Σ 调出 + Σ 调入 + Σ 盘盈 − Σ 盘亏 − Σ 报废
单位换算商品支持基本单位与整箱单位换算，销售 / 采购可任选单位，内部统一按基本单位数量核算
到期日生产日期 + 保质期天数
成本 / 毛利按批次移动加权平均成本 假设 TBD；毛利 = 售价 − 批次成本

6.4 预警与通知

预警触发条件通知方式 / 对象
临期预警批次到期日前 N 天（默认 30，可配置）仓管员、业务员、门店主管；App 推送 + PC 待办
过期预警批次已到期仓管员、管理员；强制进入报废待办
低库存预警商品库存 ≤ 安全库存采购员、管理员

信用额度超限处理方式由管理员配置：

  • 「仅警告」：允许开单，但提示风险；
  • 「拦截并需审批」：超限单据进入待审核，需有权限者放行 假设 TBD 默认拦截。
