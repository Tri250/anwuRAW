# v1.6.14 Stage-Timing Baseline

Recorded 2026-10-31 on the v2.0 development sandbox (3-core Linux, 6 GB RAM),
software rasterizer — for regression detection only, not representative of real
GPU performance. JSON source of truth: `v1.6.14-baseline.json`.

| metric | value |
|--------|-------|
| adapter / backend | llvmpipe (LLVM 20.1.2, 256 bits) / Vulkan |
| stage-timing probe | active (`RAPIDRAW_STAGE_TIMING=1`) |
| preview 1920x1080 (portrait params, 24 frames) | wall mean 2410.8 / P50 2227.5 / steady P95 2322.5 / max 4858.2 ms |
| preview steady (warm caches) | mean 2304.4 / P50 2227.5 / P95 2322.5 ms |
| preview stages cold | guided 1600.0 ms, main 2392.1 ms (flare/blur n/a — params enable none) |
| preview stages warm | guided 0.0 (GF coeff cache hit), main 2190.1 ms |
| export 9000x5000 16-bit | wall 75426.9 ms, guided 2515.1 ms, main 69131.3 ms (15 tiles) |
| memory | peak RSS 3044 MiB, export growth 2170 MiB, base 257 MiB → **growth ratio 8.43x** |

Notes for later stages:

- **Memory growth ratio 8.43x far exceeds the plan's ≤ 2.5x target.** The export
  working set (f16 tile textures + readback buffers + allocator arenas on top of
  the 45MP 16-bit base) is a known v2.0 optimization target. Until a compliant
  baseline is recorded, `compare-perf.mjs` treats 2.5x as a warning and gates on
  relative worsening (+10%) instead.
- Warm `guided 0.0` confirms the GF coefficient cache; cold `main` includes
  first-use pipeline compilation, which is why steady-state wall clock is the
  gated number.
- blur/flare stage fields read 0 because the portrait params enable no
  sharpness/halation/glow/flare adjustments; stages with those params enabled
  will populate them (probe verified end-to-end on encoder-level timestamps).
